# ADR-0010 — Android via a Capacitor wrapper; the PWA remains the primary app

**Status:** accepted (v2)

## Context

Readers want "an app". Store accounts cost money (Google Play: one-time
US$25; Apple: US$99/year); a PWA and a sideloaded APK cost nothing.

## Decision

- The PWA is primary: manifest with PNG + maskable icons, screenshots,
  shortcuts (Continue, Library, Offline), an install prompt shown only after
  the reader has started a story, and an update banner (the service worker
  waits for consent before swapping versions).
- `apps/mobile` wraps the built app with **Capacitor 7** (Node ≥ 20 — Capacitor
  8's CLI needs Node 22). The WebView serves the app from `https://localhost`;
  a remote stories origin is therefore always a different origin (the online,
  non-opaque mode). With no stories origin configured, the content plane is
  bundled into the APK and every story runs in the opaque sandbox.
- `.github/workflows/android.yml` builds a debug APK artifact for free.
- A Trusted Web Activity (Bubblewrap) is the documented alternative when the
  PWA should be listed on Google Play without a WebView wrapper.

## Consequences

- Android System WebView is Chromium, the engine the audit runs on —
  sandboxed iframes, `MessagePort`, IndexedDB, and Blob URLs are exercised
  there. On-device verification is still a manual step (STATUS.md).
- A native project lives in `apps/mobile/android` (generated by `cap add`,
  committed so it can be opened in Android Studio).
